# Accessibility pass (WCAG 2.2)

Run on the rendered page. Each row names the success criterion and its level, what to look at, and how to measure it in the browser. A failure of a level A or AA criterion is P1, and P0 when it closes the task to someone (a control unreachable by keyboard, a keyboard trap, a form that cannot be submitted without sight). A level AAA criterion is a P3 recommendation and is never reported as an AA failure.

## Perceivable

| Criterion | Look at | Measure |
|---|---|---|
| 1.1.1 Non-text content (A) | Every image that carries meaning has a text alternative that says what it shows; decoration has `alt=""` or `aria-hidden="true"`. | List `img`, `svg`, `canvas` and CSS images that carry content; read `alt` and the accessible name. |
| 1.3.1 Info and relationships (A) | Landmarks (`header`, `nav`, `main`, `footer`), headings that step one level at a time, real lists and tables, every input tied to its label. | Read the accessibility tree; a placeholder alone is not a label. |
| 1.4.1 Use of colour (A) | Error, success, required and selected states carry text or an icon besides the colour. | Look at each state with colour ignored. |
| 1.4.3 Contrast, minimum (AA) | Body text 4.5:1, large text 3:1. Large text is the threshold `DESIGN.md` declares; without one, WCAG's own: 18 pt, or 14 pt bold. | Ratio from the painted foreground and background; write the pair and the ratio. Check hover, focus, disabled and placeholder text too. |
| 1.4.4 Resize text (AA) | Text grows to 200 % with nothing cut or overlapping; zoom is never blocked. | Set the root font size to 200 % in the session; read the viewport meta for `user-scalable=no` or `maximum-scale=1`. |
| 1.4.10 Reflow (AA) | At 320 CSS px wide, no horizontal scroll for text content (data tables and maps may scroll inside themselves). | `scrollWidth` against `clientWidth` at 320 px. |
| 1.4.11 Non-text contrast (AA) | Field edges, icons that act, focus rings and chart marks reach 3:1 against what is next to them. | Same ratio method. |
| 1.4.12 Text spacing (AA) | Content survives line height 1.5, paragraph spacing 2 em, letter spacing 0.12 em, word spacing 0.16 em. | Inject those styles in the session; look for clipped or overlapping text in fixed-height boxes. |

## Operable

| Criterion | Look at | Measure |
|---|---|---|
| 2.1.1 Keyboard (A), 2.1.2 No keyboard trap (A) | Every action works without a pointer, and focus can always leave a widget. | Tab and Shift+Tab through the page; Enter and Space on each control; Escape in dialogs and menus. A clickable `div` with no role or tab stop is a finding. |
| 2.1.4 Character key shortcuts (A) | A shortcut of one letter, digit or symbol works only while its widget has focus, or can be turned off or remapped. | Focus a text field, type the shortcut key; nothing but typing may happen. |
| 2.2.2 Pause, stop, hide (A) | Carousels, tickers and anything moving for more than 5 seconds can be paused; they stop on hover and focus. | Wait, hover, focus; look for a pause control. |
| 2.3.3 Animation from interactions (AAA) | Motion set off by scrolling or clicking can be turned off; `prefers-reduced-motion: reduce` leaves the final readable state. | Context with `reducedMotion: 'reduce'`, then `document.getAnimations()`. The floor already requires the fallback, so its absence is a floor finding, P1. |
| 2.4.1 Bypass blocks (A) | A skip link is the first tab stop and lands on `<main>`. | First Tab, then Enter; read `document.activeElement`. |
| 2.4.3 Focus order (A) | Tab order follows the visual order. | Record the bounding box of each stop; a jump backwards on the page is a finding. |
| 2.4.7 Focus visible (AA) | Every stop shows a ring, at once. | Computed outline or box-shadow at the stop; a `transition` on either means it fades in. |
| 2.4.11 Focus not obscured, minimum (AA) | A sticky header, cookie bar or chat bubble never covers the whole focused element. | Compare the focused box with the boxes of fixed and sticky elements. |
| 2.4.13 Focus appearance (AAA) | The ring is at least as large as a 2 px outline around the control, at 3:1 against the unfocused state. | Recommendation only. |
| 2.5.7 Dragging movements (AA) | Anything done by dragging (reorder, resize, slider) also works with single clicks or taps. | Look for buttons or a menu beside the drag handle. |
| 2.5.8 Target size, minimum (AA) | Pointer targets are at least 24 x 24 CSS px. Exceptions: a 24 px circle centred on the target overlaps no other target or circle; another control on the page does the same thing; the target is a link inside running text; the browser draws it unstyled; the size is essential. | `getBoundingClientRect` on every control; test the exceptions before filing. Under 44 px on touch is a P3 recommendation, not a failure. |

## Understandable

| Criterion | Look at | Measure |
|---|---|---|
| 3.1.1 Language of page (A) | `lang` on `<html>` matches the text (`pt-BR`). | Read the attribute. |
| 3.2.6 Consistent help (A) | Help, contact or chat sits in the same place relative to the rest on every page that has it. | Compare the pages in scope. |
| 3.3.1 Error identification (A), 3.3.2 Labels or instructions (A) | A failed submit names each invalid field in text next to it, tied by `aria-describedby`; required fields are marked in words or a symbol explained once. | Submit empty and invalid; read the error text and its relationship. A red border alone is a finding. |
| 3.3.7 Redundant entry (A) | Within one process, data already given is filled in or offered, not typed again. | Walk the whole flow. |
| 3.3.8 Accessible authentication, minimum (AA) | Sign-in allows paste and password managers (`autocomplete`), or offers a method with no memory test. | Paste into the password and code fields; read `autocomplete`. |

## Robust

| Criterion | Look at | Measure |
|---|---|---|
| 4.1.2 Name, role, value (A) | Icon-only buttons have a name; toggles and chips expose their state (`aria-pressed`, `aria-expanded`, `aria-selected`) matching what is shown. | Accessibility tree. |
| 4.1.3 Status messages (AA) | Errors, a saved notice, a cart count that changes are announced without moving focus, as one sentence ("3 itens no carrinho"), not a bare number. | Look for `role="status"`, `role="alert"` or `aria-live` on the element that changes. |

## Keyboard beyond WCAG

The page must not take over the browser's own shortcuts (Ctrl or ⌘ with L, T, W, N, R) globally. If a shortcut must reuse one, it applies only while a specific element has focus. A global takeover is P2.
